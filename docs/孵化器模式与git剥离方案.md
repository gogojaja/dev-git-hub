## ✅ 可稳定达成效果

### 1. 孵化器模式定位（核心决策）

**DevProjectTeamSkill 定位升级为「项目孵化器」**：
- **产出**：初始方案、架构决策（ADR 草案）、可行性分析、技能/工具定义
- **不做**：实事落地（编码/部署/运维）——落地交被孵化项目自身
- **孵化生命周期**：方案调研 → 可行性五维 → 孵化决策 → **移交清单**（方案+评审+产物 → 独立项目/运营者）→ 后续仅登记引用（不内嵌）

> **证据**：EV-303[high]（AGENTS.md 已隐含「本体即技能源码」语义）、EV-305[medium]（PMI 组合生命周期：创意→评估→选中→独立管理）

### 2. git 功能剥离（本项目只留最小本地 git）

| 功能 | 归属 | 说明 |
|------|------|------|
| **本地最小 git**（init/status/commit/log/diff） | **本项目保留** | 技能库自身版本管理必需（提交/固化用） |
| **复杂远端操作**（GitHub 真实IP推送/镜像双推/网络异常处理/access 标准） | **剥离到 dev-git-hub** | 经 MCP/CLI 工具调用，非内嵌实现 |
| **局域网 git 基建**（LAN 中枢/Windows 副本/WAN 灾备） | dev-git-hub（已建） | 本项目仅保留 sync_policy.md 引用登记 |

**剥离方式**：`tools/github_push.py` / `mirror_push.py` / `github_ip_refresh.py` / `restore_github_push.sh` / `github_access.md` → 迁至 dev-git-hub，本项目经 `工具调用`（dev-git-hub 提供 CLI/MCP）使用；AGENTS.md 命令区 git 行改为「调用 dev-git-hub 工具」说明。

> **证据**：EV-301[high]（现状 5 工具内嵌）、EV-302[high]（dev-git-hub 已建可承接）、EV-306[medium]（松耦合集成：经工具调用而非内嵌）

### 3. 成熟技能/工具独立化机制（逐步）

**三判据评估**（防过度拆分，EV-307）：
| 判据 | 判定 |
|------|------|
| **复用率** | 跨项目/跨仓库反复使用 → 倾向独立化 |
| **独立性** | 与技能库无强耦合、可独立解释 → 倾向独立化 |
| **维护成本** | 独立后自管理成本 < 内嵌维护成本 → 独立化 |

**流程**：现有技能/工具若达三判据 → 孵化器出「独立化方案」→ 评审 → 移交清单 → 独立项目运营 → 本库登记引用。

> **证据**：EV-307[medium]（反信号：不能一刀切，按判据逐项评估）

### 4. 新增「孵化器立项阶段」技能（下一步优化内容）

本方案识别：现有 `role-project-init` 是「业务项目启动」，缺 **「孵化器立项阶段」**——启动一个项目前的方案调研/可行性分析独立流程：

| 环节 | 内容 |
|------|------|
| 方案调研 | 需求/竞品/技术路线初调研（复用 best-practice-solution Research） |
| 可行性五维 | 技术/经济/合规/资源/时间可行性（对齐 PMBOK 启动 + 本库五维可行性） |
| 孵化决策 | 继续孵化 / 放弃 / 移交独立项目 |
| 移交清单 | 方案+评审+证据卡+ADR → 独立项目 |

> **证据**：EV-304[high]（现有 role-project-init 含 check_ready 可升级复用）、EV-308[high]（缺口：无独立孵化器立项流程）、EV-305[medium]（PMBOK 启动过程组）

## ⚠️ 理论最优效果与当前限制

| 限制/反信号 | 说明 | 缓解 |
|-------------|------|------|
| git 剥离后本项目远端操作为跨项目调用 | 项目内高频本地 git 与远端操作需区分 | 本地最小保留；远端经工具调用（项目内仍有 mirror_push 代理亦可保留薄封装） |
| 孵化器「只出方案不落地」边界 | 部分技能被反复使用但未独立 → 本库膨胀 | 三判据评估逐项独立化，未达判据暂留 |
| 立项阶段新增流程 | 与既有 role-project-init 职责重叠 | 既有保留给业务项目；新增孵化器立项（复用其 check_ready 等环节） |
| 过度独立化风险 | 拆分过多管理分散 | 反信号：独立化后若调用率下降/无人维护 → 回收入本库保持单源 |

## 决策记录草案

- **标识**：ADR-2026-08-30-001（待架构角色正式编号）
- **决策**：本项目升级为「项目孵化器」（只出方案不落地 + 成熟技能/工具独立化 + 新增孵化器立项阶段）；git 复杂远端操作剥离到 dev-git-hub（经工具调用），本项目保留本地最小 git
- **选项**：
  - A. 维持现状（git 内嵌 + 无独立化机制）→ ❌ 本库持续膨胀 + git 与硬件耦合
  - B. **孵化器模式 + git 剥离（本方案）** → ✅ 职责分离、解耦、可演进
  - C. 全部分拆成独立项目 → ❌ 拆分过散、无孵化器阶段过渡
- **理由**：EV-303/306/307/308 证据链
- **已验证**：dev-git-hub 已建（AUTH-014）；role-project-init 已含立项/check_ready 可复用
- **不确定**：git 剥离后工具调用往返成本（需实测）；三判据阈值需校准
- **未关闭风险**：剥离后远端操作依赖 dev-git-hub 可用性（保留薄封装兜底）
- **反信号**：独立化后调用率下降/无人维护 → 回收入本库；本项目长期无新孵化项目 → 孵化器定位不生效
