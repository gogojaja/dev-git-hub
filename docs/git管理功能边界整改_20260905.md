> 契约基线：dev-git-hub README §六「维护接口契约」——本项目 = git 基建单一信源，DevProjectTeamSkill 不保留实现，仅引用+代理调用。
> 结论：远端复杂操作代理化已兑现；发现 4 处边界遗留/漂移，本文档给出整改项并记录执行。

## 二、整改项

### R-1 init_mac_bare_repos.py 实现遗留（未剥离）

- **问题**：DevProjectTeamSkill/tools/init_mac_bare_repos.py（14KB 完整实现：扫描本地无远程仓库 → Mac 建 bare → 加 hub remote → 推送/克隆）属 git 基建构建能力，与本项目 install_mac.sh 职责域重叠，违反「不保留实现」契约。
- **整改**：实现整体迁入 `dev-git-hub/tools/init_mac_bare_repos.py`（自包含：标准库 + git + ssh，零依赖可迁移）；DevProjectTeamSkill 侧替换为标准薄代理（`_hub_proxy.run_proxy` 模式，命令/参数完全兼容）。
- **后续建议（不阻塞）**：MAC_USER / MAC_HOST / MAC_BARE_BASE / DEFAULT_SCAN_DIRS 仍为脚本内常量，建议后续纳入 config.yaml 解耦层（脚本已支持 --mac-host / --scan-dir 覆盖）。

### R-2 load_secret.py 双份实现漂移风险

- **问题**：两仓各有一份 load_secret.py，内容存在差异，无单源声明。
- **核查**：diff 仅 1 行——ROOT 推导方式不同：技能库侧支持 `PROJECT_ROOT` 环境变量覆盖，hub 侧固定为自身仓库根。两者相对各自所在位置**均正确**，属位置自适应而非功能分叉。
- **整改**：不合并为单文件（技能库侧被 `nightly_code_complete.py` 以模块方式 `from load_secret import load` 导入，无法代理化；且技能库凭据含非 git 类如 `llm_token`）。处置 = 双份保留 + 双向头注释声明「姊妹文件，功能须保持一致，修改须双侧同步」，消除隐性漂移。

### R-3 github_access.md 标准文档漂移

- **问题**：技能库 `.trae/skills/references/github_access.md` 104 行 vs 本项目 134 行，内容分叉（hash 不同），违反「标准以本项目 references/ 为单一信源」。
- **整改**：以本项目 `references/github_access.md`（134 行）为源，全量覆盖同步至：
  1. `DevProjectTeamSkill/.trae/skills/references/github_access.md`
  2. `DevProjectTeamSkill/.trae/skills/shared/references/github_access.md`（单源铁律副本）
  3. 已发行插件：`dist/dev-project-team-skill/skills/references/`、`dist/dev-project-team-skill/skills/shared/references/`
  4. 已安装插件缓存：`~/.qoder-cn/plugins/cache/local/dev-project-team-skill/skills/{references,shared/references}/`
- **验证**：同步后各副本与源文件 SHA256 一致。

### R-4 restore_github_push.sh 硬编码路径

- **问题**：DevProjectTeamSkill/tools/restore_github_push.sh 硬编码 `/Volumes/BR256G/dev-git-hub/...` 与 `/Volumes/BR256G/DevProjectTeamSkill`，未走 `_hub_proxy` 三级动态解析，换机即失效，违背可移植性原则。
- **整改**：重写为与 `_hub_proxy.py` 同构的三级解析（`DEV_GIT_HUB_ROOT` 环境变量 > 同级目录约定 > `.hub_root` 配置），PROJECT_ROOT 动态推导为本仓库根，再 `exec` 转发至本项目对应脚本。
